# 用户旅程与协作输出

关键流程由用户确定后使用；先整理的草稿保留候选与未知。可在一份文档中承载旅程图、分工表和异常说明，形式按任务裁剪。

| 内容 | 写清什么 |
| --- | --- |
| 任务与完成条件 | 目标用户、当前任务、范围及取得什么结果才算完成 |
| 用户旅程 | 入口、输入、过程、输出、交付及关键交接 |
| 人机分工 | 步骤、AI 做什么、人做什么、确认点、为什么要人；必要规则或系统约束按实际关系加入 |
| 控制权与确认点 | 谁在何时接手或点头，成本、主观、担责的实际依据，已有决定如何复用 |
| 异常路径 | 信息不全、失败、改主意、不满意时的触发、行为、保留内容和结束／继续状态 |
| 决定与缺口 | 观察事实、推断、拟议设计、用户确认和实际验证的状态，具体下一步 |

按任务而非按钮拆步骤，岗位不自动等于 Agent 数量。必要的输入、输出和完成要求用于交接，不扩展为完整模型、工具或规则方案。

确认点必须有实际理由；便宜、可撤回、可局部修改的步骤不例行增加暂停。异常处理按已知限制写，未确定的责任、能力或时限保持待定，不凑人工角色与队列。

检查旅程、分工、范围和异常是否一致，用户是否能取得本版结果。文档和图已生成不等于自动化已实现、任务已实际完成或用户已验证交付成功。
