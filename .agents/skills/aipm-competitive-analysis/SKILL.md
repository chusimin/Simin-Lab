# 竞品分析与差异化

把竞品信息用于当前一项决定，形成可追溯的比较与差异化候选。先共同判断，最终采用的方向由用户确定，再写文档；方向选择不自动证明需求、商业结果或自身实现能力。

## 明确目的与范围

先读已有问题、决定和证据，辨认本次目的：0～1 看市场、格局与空白；1～N 看对手功能、差评和迭代依据；对手出招看为什么做与用户是否买账；定价看公开价格、计费条件与已有成本资料。原因无证据时保留假设，不把目的变成泛泛行业盘点。

可以从一句决定或尚待明确的目的开始，只补影响对象选择、可比性或差异化判断的信息。用户已有明确目的与方向时复用；有新冲突才指出影响。只有一个产品且无横向比较目的时使用产品拆解，不制造竞争对象，也不要求先逐个完成全套拆解。

## 找竞品并选择维度

| 类别 | 纳入依据 |
| --- | --- |
| 直接竞品 | 做同样的事，争取同样的人 |
| 间接竞品 | 以不同方式满足同一需求 |
| 替代品 | 用户目前采用的凑合办法，可包含人工或既有流程 |
| 潜在竞品 | 有能力进入但尚未进入；能力依据不足时只作候选 |

按目的取相关对象并说明理由，不强制凑齐四类。没有证据的替代办法不得写成真实采用。

确定目标用户、同一真实任务、输入与完成标准，再选会影响决定的维度：市场阶段与竞争情况、定位、用户旅程与完整产物、技术流程与人机分工及单个 Agent、模型列表与理由、数据来源与成本。按需裁剪，不填满所有格，也不以功能数量代替任务完成。

记录访问日期、版本、账户或套餐、模型、权限与输入条件；条件不一致时对齐、缩小结论或说明可比范围，不能直接给性能排名。市场规模、用户量、收入、成本需来源与统计口径；第三方估计保留范围，不补精确数值、权重或占有率。

## 收证据并横向解释

可用已有拆解，也可直接读取使用记录、完整产物、官网、帮助、财报、定价、评论、社区测评、融资招聘与第三方数据。自己走主流程须在实际访问和操作授权内，渠道不意味着必须付费或订阅；无法访问或付费未授权时，交已有依据与具体缺口，不声称试用。

每个关键数据和判断标来源、时间、条件与证明范围。官网原文支持对方公开声称，一次使用支持该条件下的观察，评论支持该评论者表达了什么；少量差评不证明普遍需求、市场空白或规模。售价不证明对方成本，融资招聘不单独证明产品成功或即将进入。

沿用页面事实、合理推断、尚未确认。官方原文须打开核对，已完成提示须检查完整产物；仅限截图的任务不借外界知识补出流程。界面模型、工具、角色与步骤不证明后台路由、RAG、Agent 数量或训练方式。

比较各产品完成什么、用户还需做什么、在哪些条件下卡住，以及差异如何影响当前决定。一次成功或失败不能直接证明稳定能力或永远做不了；冲突证据保留来源和条件，不只取符合当前方向的材料。

## 挑战方向与差异化

当前有自己的产品方向时，给出最有说服力的反方论证：为什么相关竞品可能成功，而当前方向可能失败。论据对应已有来源，假设与缺口显式保留；论证用于暴露弱点，不创造新的市场事实。

从用户、需求、场景寻找更垂直、更深、更专的候选，核查课件句式“盯 X 用户，他最在乎 Y，竞品做不了，因为 Z”：X 的依据是什么，Y 为什么重要，Z 在什么能力与条件下限制对手，自己的方向凭什么能提供差异。

只观察到某次失败时写该条件下未完成；没看到功能时写未找到支持证据；结构性限制不清时将 Z 保留为待验证假设。不能把暂未找到功能写成永远做不了，也不能默认自己的实现已成立。

结论可以是补证据、暂不跟进、没有充分差异化依据，或采用附条件的方向；不强制评分、排名或选赢家。最终取舍由用户确定，已有决定直接复用；向研究、立项或版本取舍交接具体验证问题，不自动转为 MVP、立项通过或最终定价。

## 确认、撰写与完成

展示比较结论、反方论证、候选方向、依据和未知。用户确定关键判断后，读取[分析文档与证据要求](references/competitive-report.md)整理文档。明确要求先整理已有材料时可交标明假设的草稿，不把未确认方向写成已决定。仅讨论时不写文件，保存沿用用户指定位置或当前项目文档位置。

完成时明确当前决定、对象纳入理由、可比任务与条件，关键判断可追溯，差异化 X、Y、Z 有依据或状态，用户选择与下一步具体未知得到保留。资料不足时限定结论，不以表格完整作为完成条件。

本项不执行完整用户研究、需求排序、版本范围设计、商业投入决定、正式模型评测、当前产品技术实现、原型或 PRD。后续 Skill 未接入时只说明职责，不声称已调用。
