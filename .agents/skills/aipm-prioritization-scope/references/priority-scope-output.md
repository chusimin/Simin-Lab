# 优先级与版本范围输出

用户确定关键取舍后使用；明确要求先整理时可写草稿并保留未定项。可以合并为一份文档，按任务裁剪，不因字段存在补造内容。

| 内容 | 写清什么 |
| --- | --- |
| 当前目标与假设 | 面向谁、完成哪项任务、本版要验证或改善什么；已有决定及其来源 |
| 候选需求 | 需求连回哪个痛点、依据与状态，多个实现方式如何比较 |
| 优先级依据 | 实际采用的 Kano 或四象限判断，分类、价值、成本的含义及缺口 |
| 必须做 | 保留原因、与假设及可用任务的关系、必要依赖 |
| 明确不做 | 排除项及理由，不将其混入本版功能说明 |
| 以后再说 | 本版延期项及理由，不作为未来版本承诺 |
| 通过标准 | 可观察结果、口径、条件、已有依据和未定项 |
| 决定与下一步 | 用户确认的范围、尚待验证的假设、具体补证据行动 |

检查需求是否连回问题，范围是否能支持取得本版结果，依赖和异常是否与范围冲突。没有成本或效果数据时保持未知；定性判断说明依据，情景估计注明假设。

用户确认只表示当前取舍已决定。研究验证、技术确认、测试和交付状态分别记录；不把文档已生成写成 MVP 已通过。
