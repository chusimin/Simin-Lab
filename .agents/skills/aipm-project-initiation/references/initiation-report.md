# 立项报告输出

关键投入判断由用户确定后使用。课件八块可以在一份文档中承载，决策摘要按需要单独提取，不强制添加审批流程或多份文件。先整理的草稿须保留未定项。

## 默认交付形式

用户已指定最终立项报告采用“随身记 H2 全景规划”案例的 HTML 表现形式。默认交付可直接在浏览器打开的单文件 `.html`，CSS 与报告交互脚本内嵌；过程草稿可用 Markdown，用户另指定格式时按其要求。此项是用户的呈现偏好，不是课件新增的方法论。

从[HTML 版式模板](../assets/initiation-report-template.html)复制后填入当前项目内容，替换项目名称、标题、状态、版本、日期及示意槽位。保留深色固定左侧目录、米白网格背景、蓝色与青柠强调色、圆角卡片、深色结论块、表格和折叠附录；保留目录锚点跳转、当前章节高亮、阅读进度及窄屏单列阅读。模板的章节名称可按项目调整，课件八块内容仍需承载。

开头先给一页纸结论，再展开论据、取舍、方案、投入与计划。指标卡、比较表、流程图及版本节奏按已有材料选择，不为版式完整编造数据、填满固定卡片或固定版本数量。来源、假设、待核查项及未定决定保持可辨认；详细材料可放折叠附录，实际来源链接按项目填写。

模板只复用案例视觉和阅读交互，业务名称、竞品、数字、指标、组织角色、业务公式及结论由当前项目提供。沿用模板内的报告交互，不复制原案例的平台注入、追踪脚本或相对平台资源。正文无需依赖外部字体、CSS、脚本或网络服务。

保存后在浏览器核查首屏和长页阅读、目录跳转与高亮、阅读进度、折叠内容和窄屏排版，检查来源链接及未替换的示意内容。明确标注草稿或已确认状态；生成 HTML 不改变立项批准状态。交付报告文件的可点击路径。

## 内容与一致性

| 内容 | 写清什么 |
| --- | --- |
| 决策摘要 | 做不做、投多少或投入边界、什么时候停；已决定、条件与待定分开 |
| 背景与问题 | 为什么现在做、具体用户任务与问题及依据 |
| 用户与场景 | 谁、问题造成什么影响、证据支持到何种程度 |
| 市场与竞品 | 机会在哪、凭什么是我们，来源、推断与未知可辨认 |
| 目标与成功指标 | 怎么算做成，口径、条件与依据；拟定要求与实测结果分开 |
| 方案与第一版范围 | 承接已定范围，做什么、明确不做什么，待验证假设是什么 |
| 投入与计划 | 人、钱、时间、阶段，估计来源、假设、限制及待核查项 |
| 风险与停止条件 | 实际风险、出错谁兜、什么情况下停，责任与未定项明确 |

AI 论证保留适用性、效果要求、AI／规则／人的分工、数据来源与负责人、单次成本及口径，不将未知补成已验证能力。

核查摘要、范围、投入、成功指标和停止条件是否一致。缺少商业、技术或效果依据时说明它影响哪个决定及如何补证据；不凑分、不引入统一 ROI 门槛、不承诺情景估计。

用户批准、研究证据、技术确认、实际测试和业务回报分别记录。报告完成只代表论证与决定得到整理。
