# 课件方法索引

来源：[需求分析与立项课件](https://w3d2-3-requirements-initiation.vercel.app/)。正文核对日期：2026-10-08（Asia/Taipei）。页码辅助定位，版本变化后按标题查找；执行 Skill 不要求每次访问网站。

| 定位 | 课件原方法 |
| --- | --- |
| 第 16 页「该不该用 AI」 | 重复性高、标准化程度高、人力瓶颈明显；再比较流程改进 |
| 第 68 页「过三问 = 决策矩阵」 | 用户买不买、公司赚不赚、开发难不难，对应市场、钱、能做；示例用 1～5 分，结论为做、不做、有条件做 |
| 第 69 页「AI 多问四句」 | 该不该用 AI：重复、标准、缺人，改流程更便宜吗，模型变强更值钱吗；效果门槛及人工比较；AI／规则／人的分工；数据来源、负责人和单次成本 |
| 第 70 页「立项报告长什么样」 | 决策摘要、背景与问题、用户与场景、市场与竞品、目标与成功指标、方案与首版范围、投入与计划、风险与停止条件 |

用户已确认“三个都占才用 AI”，本版不增加例外。三问与 AI 四问均需依据，三条件满足不等于正式立项已成立。评分不强制完整，缺少依据可保留未知或给条件性建议；用户确定投入和停止条件后撰写，复用已有决定，要求与实测分开。

证据状态、确认节奏、非商业事项的适用性说明及产物裁剪属于工作台执行方式。课件未提供通用加总分数、ROI 公式、模型选型、知识库治理、成本估算或评测执行体系；保留专项缺口，案例名称、数字、评分和阈值不通用化。

最终默认以“随身记 H2 全景规划”案例版式交付单文件 HTML，是用户于 2026-10-08 指定的呈现要求；只复用视觉与阅读交互，内容仍依据课件方法及当前项目材料。具体形式由[立项报告输出](initiation-report.md#默认交付形式)维护。
