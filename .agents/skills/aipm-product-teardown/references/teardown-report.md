# 产品拆解报告与证据要求

在用户确定关键判断后读取。按当前问题与材料裁剪，可合并成一份文档；缺层或缺异常证据时允许报告有范围，不补造内容或凑固定数量。

## 报告内容

| 内容 | 要写清什么 |
| --- | --- |
| 任务与定位 | 用户、场景、任务、输入、完成标准、替代办法；产品、日期、版本、套餐与观察条件 |
| 用户旅程 | 入口、输入、过程、输出、交付；用户动作、页面反馈、确认点、异常及结果需补的工作 |
| 完整输出物 | 原始产物或可追溯位置、任务完成情况；完成提示与产物实际存在及可用分别记录 |
| 流程与人机分工 | 按工作组织的流程，AI 做什么、人能做什么、在哪确认及原因的证据状态 |
| 单个 Agent（有依据时） | 规则、输入、任务、输出、工具、验收；未披露内容保持未知 |
| 模型与基础层 | 公开披露与可观察信息、数据来源、收费、自有方法；未知与证明范围 |
| 判断与交接 | 用户采用的关键解释及依据、确认状态、冲突、具体补证据动作 |

观察到的产品安排与对团队意图的解释分开，用户确认当前分析与研究证据充分程度分开。用户明确要求先整理材料时标为草稿并保留未知，不将未确认判断写成已确定方案。

## 证据表

按需选择字段，关键判断必须能够追溯。

| 字段 | 内容要求 |
| --- | --- |
| 判断或观察 | 产品在什么任务与条件下发生了什么，以及该信息支持哪项判断 |
| 来源与定位 | 截图编号及页面原文、使用记录、完整产物、官方链接或材料位置 |
| 范围 | 日期、版本、输入、套餐等会影响结论的条件 |
| 状态 | 页面事实、合理推断、尚未确认；公开声明注明为已核对声明 |
| 依据与限制 | 推断由哪些事实推出；哪些内部机制、异常或效果仍不能确认 |
| 下一步 | 查哪个材料、观察什么结果或换哪项任务，能够减少哪个未知 |

只根据截图的任务不引用外界资料补出截图行为；补查授权明确时将新来源单列。不能由菜单确认实际模型调用，由角色名称确认后台 Agent 数量，由隐私改进条款确认系统在学习，或由售价确认推理成本。

## 交付前检查

- 定位与流程服务于真实任务，旅程连接输入和完整交付。
- 事实、推断、未知和公开声明的证明范围得到区分。
- 分工按工作划分，确认点的存在与其原因分别有依据或状态。
- 用户确定的范围与判断得到保留，未观察到的内容没有补成事实。
- 缺口具体可查，正式选型、数据方案、评测或产品设计仅作交接。
