# AI 产品拆解

理解一个产品如何把真实任务交付成可用结果。先共同观察和判断，由用户确定分析范围与关键解释，再整理报告；不从拆解结果自动决定当前产品方案。

## 进入任务

先读已有材料与决定，明确产品、目标用户、任务、输入和完成标准。可以从产品入口或截图开始；任务不清时只补会改变判断的信息，已有明确任务直接复用，不要求先填完整表格。

记录访问日期、版本、账户或套餐、模型选择、权限等影响观察的条件。无法访问时分析现有材料并提出取证计划，不声称已经实测。仅限截图的任务只依据截图，不用宣传、外界知识或常识补出行为与流程。

## 按真实任务分层理解

按当前问题裁剪深度，不要求各层资料齐全、固定异常数量或固定产品决定数量。

| 层次 | 要判断的内容 |
| --- | --- |
| 定位 | 当什么场景时，谁想完成什么任务，得到什么结果；没有产品时如何做，替代了什么。公开定位与观察到的用途分开，用户不能泛指所有人 |
| 用户层 | 入口、输入、过程、输出、交付；用户做什么、页面反馈什么、在哪里决定、结果还需改多少。保留完整产物及条件，不仅看按钮与完成提示 |
| 技术层 | 按工作拆流程与人机分工，检查可辨认任务单元的规则、输入、任务、输出、工具和验收；内部信息未知时保留未知 |
| 模型层 | 谁在想、谁在生成；能否更换、换后怎样。区分界面可选、官方披露和本次能确认的调用，不由模型菜单补出后台路由 |
| 基础层 | 数据从哪来、是否越用越好；什么在烧钱、如何收费；模型之外积累了什么方法。公开售价不等于实际算力成本，改进条款不证明已在学习或效果改善 |

角色影响任务时，按实际关系补使用者、买单者、验收者；同一人可兼任，不因面向企业就凑齐三类独立人员。定位应能区分该产品，官方说明不能单独证明真实采用。

## 用户旅程与控制权

沿入口到交付还原正向流程，观察信息不全、失败、中途改主意、不满意时发生什么。未观察到的异常写尚未确认，不补造追问、退款、恢复或局部修改能力；没有看到也不证明不支持。

每一步记录用户动作、页面反馈、用户决定及截图编号、原文或记录。产品或 Agent 说已完成时，回到实际页面或产物核对是否生成及可用。分析用户能改什么、何时介入与承担多少工作，回到目标用户判断控制权，案例中的用户类别与形态不固化成规则。

## 流程、人机分工与单个 Agent

先想任务由人完成时有哪些工作与交接，再对照产品的 AI 工作、人能介入的工作与确认点。岗位映射用于理解任务，不证明后台存在同样数量的 Agent。

问答、固定步骤、按任务变化的步骤、角色交接是 Chatbot、Workflow、Agent、多 Agent 的页面信号；拿不准时换任务观察。信号不直接证明实现、Agent 数量或模型路由，合理解释标推断。

确认点的课件依据是成本高、主观、担责；现有确认是否存在与为什么设在这里分开记录。原因缺依据时作解释假设；便宜、可撤回、能局部改的动作不应例行停下来确认，不默认所有现有确认点都合理。

有依据的单个角色或任务单元，检查规则、输入、任务、输出、工具与什么样算完成。没有披露的 System Prompt、工具配置和执行步骤保持未知。当前任务验收标准与对方团队披露的标准分开，不声称团队正在使用自己提出的标准。

## 证据与补查

沿用课件三分法：**页面事实**是直接可见的内容，**合理推断**说明由哪些事实推出，**尚未确认**表示证据不足。官方原文证明公开声明存在，其对内部运行的证明范围另行判断。用户认同分析不会把未知的团队动机变成事实。

AI 说官方写了时打开原文核对。按需查模型框、帮助、更新日志、价格页、隐私政策、技术博客或访谈；查不到时记录查过哪里与具体未知。规则提出要求，算法是做到要求的办法；资料不足时不补造训练方式、成本、效果或商业回报。

冲突材料保留来源与条件，解释其影响。注册、付费、订阅、对外联系按已有实际授权处理，资料渠道不意味着必须购买；访问受限时交付有依据的部分与取证计划。

## 确认、撰写与完成

展示定位、任务表现、关键解释、未知及建议，复用用户已有确认；用户确定关键判断后，读取[报告与证据要求](references/teardown-report.md)整理文档。明确要求先整理已有材料时可交标明未知的草稿，不把未确认解释写成定论。仅讨论时不写文件，保存沿用用户指定位置或当前项目文档位置。

完成时，旅程连通输入与完整交付，人机分工按工作划分，关键判断有来源与状态，并指出下一步查什么或换什么任务。允许形成有限范围报告；不以各层表格填满作为完成条件。

跨产品比较交给竞品分析；本项不完成当前产品的旅程设计、技术实现、原型、PRD、立项、模型选型、RAG、数据方案或正式评测。未接入后续 Skill 时说明职责，不声称已经调用。
